# ПОЛИПЛАСТИК — основной текст для RAG, v2.1.0

Обычный запуск извлекает корпоративные инструкции и готовит чанки. HTML, картинки
для проверки и обязательная ручная сверка в обычном режиме не используются.
Обработка локальная, без LLM и внешних API.

## Запуск

Из папки с `ingest.py`, в существующем окружении:

```powershell
.\.venv\Scripts\python.exe ingest.py --input "C:\Users\Lvlup\Downloads\POLIPLASTIK.zip" --output "data\ingested" --tesseract-path "C:\Program Files\Tesseract-OCR\tesseract.exe"
```

Укажи фактический путь к своему ZIP. Пакеты прежние; переустановка для обновления
v2.0.1 → v2.1.0 не нужна. При первой установке:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-tested.txt
```

Нужен Tesseract 5 с языками rus и eng. Если модели в другой папке,
добавь `--tessdata-dir "C:\...\tessdata"`.

## Что обрабатывается

- Текст, таблицы, вложенные группы и SmartArt презентаций.
- Все 21 страницы основного текста ПВТР: страницы 3–23, OCR при **300 DPI**.
- Неизвестные изображения продолжают проходить OCR. Известный дополнительный
  скриншот пропускается только при наличии основного нативного текста на слайде.
- Известные логотипы/фотографии, дополнительные сканы форм и скриншоты интерфейса
  не попадают в основной корпус. Сопоставление идёт по SHA-256, не по имени файла.
  Поэтому образцы документов, доступные только в этих скриншотах, не включены;
  их можно извлечь диагностическим режимом или загрузить отдельными документами.
- Обложка и оглавление именно вашего PDF, заглушка iSpring, описание кейса и Excel
  со сценариями не индексируются как корпоративные правила. Причины фиксируются.

Основной текст не переписывается LLM. Качество OCR остаётся прежним: настройки
распознавания основного текста и разрешение не снижены.

## Результат

- `data/ingested/chunks.jsonl` — фрагменты для будущих эмбеддингов.
- `data/ingested/segments.jsonl` — извлечённые страницы/слайды и их источники.
- `data/ingested/report.json` — краткие результаты, предупреждения и ошибки.

`ready_for_embeddings: true` означает, что извлечение прошло без блокирующих
ошибок. Это не отметка ручной проверки и не гарантия правильности каждого символа.
Обычные предупреждения OCR не требуют прохождения отдельной страницы проверки.
Пустые/нечитаемые основные страницы и технические ошибки продолжают блокировать
готовность, чтобы не потерять текст молча.

Коды: 0 — готово; 1 — ошибка обработки; 2 — остались блокирующие проблемы текста.
Число чанков отличается от v2.0.1: основные тексты слайдов 5, 11, 12, 14 теперь
включаются без зависимости от качества дополнительных скриншотов.

При повторном запуске неизменённые документы берутся из кэша целиком: повторные
рендер страниц и OCR не выполняются. Изменение файла, моделей или настроек
инвалидирует кэш. Первый запуск v2.1.0 создаст новый кэш; старый не переиспользуется.
Результаты сохраняются снимками, а `current.json` атомарно переключается на
завершённый запуск. Для интеграции с продуктом:

```python
from ingest import load_current
snapshot, report = load_current('data/ingested')
chunks_path = snapshot / 'chunks.jsonl'
```

OCR нужен при загрузке/обновлении базы документов. При каждом вопросе сотрудника
этот модуль не запускается: будущий поиск работает по уже подготовленному индексу.

## Необязательная диагностика

Для подробного разбора изображений, обложки, оглавления и HTML-проверки добавь
`--audit`. Такой запуск медленнее, сохраняет изображения и может потребовать
ручной сверки. Для решений из HTML используется прежний параметр `--reviews`;
он автоматически включает диагностический режим.

Старый `review.html` может оставаться от предыдущего запуска. Обычный режим его
не обновляет и не использует. Режим текущего запуска указан в `report.json`.

Тесты — инструменты разработки. Они не запускаются при обработке документов
и не участвуют в работе бота. При необходимости разработчик запускает их отдельно:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe validate_corpus.py --output "data\ingested"
```

Поддерживаются PDF/PPTX; исключения и правила вашего корпуса — в `policy.json`.
Технические ограничения ZIP/размеров и блокировка одновременной записи сохранены.
На сервере обработку файлов можно выполнять отдельным worker с ограничениями
CPU/RAM; текущая поставка — локальный модуль подготовки документов.

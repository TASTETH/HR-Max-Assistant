# Что хранить в Git и что необходимо локально

`.gitignore` исключает файлы из новых коммитов, а не удаляет их с диска.
Добавление правил не убирает уже отслеживаемые файлы из истории Git.

## Код и конфигурация: оставляем в Git

| Файл/каталог | Назначение |
|---|---|
| `korsik_rag/` | Модели, индексация, hybrid retrieval, контекст, клиент LLM, CLI/API |
| `ingest.py`, `ocr_core.py`, `extract.py`, `chunks.py`, `review.py` | Сохранённый модуль OCR; `load_current()` также используется RAG |
| `policy.json` | Исключения и правила извлечения OCR |
| `document_scope.json` | Явная организация и права для SHA-256 документов; нужен для индексации |
| `docker-compose.yml` | Qdrant с постоянным volume и фиксированной версией |
| `.env.example` | Шаблон настроек без настоящих ключей |
| `scripts/init_env.py` | Подготовка локального `.env` и генерация секретов |
| `pyproject.toml` | Установка модуля и импорт из backend |
| `requirements-all.txt`, `requirements-tested.txt`, `requirements-rag.txt` | Связанные файлы установки; нужны все три |
| `requirements.txt` | Короткая ссылка на полный набор зависимостей |
| `README.md`, `ARCHITECTURE.md`, `OCR_README.md` | Запуск и описание устройства |
| `.gitignore` | Исключение локальных данных и секретов |

`document_scope.json` описывает именно ваши документы. Для публичного демо можно
подготовить обезличенный пример, а реальную конфигурацию доставлять отдельно;
для работы индексатора нужен настоящий файл по `RAG_SCOPE_FILE`.

## Не обязательны для обработки обычного вопроса

- `tests/`, `tests_rag/`: проверки разработки. Их полезно оставить в Git; при
  запуске API и вопросах они не выполняются и не занимают модельную память.
- `checks/run_search_checks.py`: операторский прогон нескольких реальных вопросов.
- `validate_corpus.py`, `run_windows.ps1`: дополнительные утилиты OCR.
- `TEST_RESULTS.md`, `VERIFICATION.md`: описания выполненных проверок.
- `requirements-ocr.txt`: отдельные диапазоны зависимостей OCR; полный проект
  устанавливается через `requirements-all.txt` с `requirements-tested.txt`.

Удалять исходники `review.py` ради скорости не требуется: обычный OCR не создаёт
страницу проверки, а файл нужен опциональному аудиту и установке исходного пакета.

## Оставляем локально, но не отправляем в Git

| Файл/каталог | Нужен локально? |
|---|---|
| `.env` | Да: настройки и секреты |
| `.venv/` | Да для запуска в этом окружении; воспроизводится установкой зависимостей |
| `data/models/` | Да: кэш весов и токенизаторов; воспроизводится download-models |
| `data/ingested/current.json` и указанный им снимок | Для индексации: canonical chunks, segments, report и остальные файлы указателя |
| `data/rag/active.json` и указанная версия | Для поиска: манифест, chunks, segments и scope согласованного индекса |
| Docker volume Qdrant | Для поиска: соответствующая коллекция векторов; это не обычная папка исходного кода |
| Корпоративные PDF/PPTX и другие исходники | Для нового OCR; не нужны при каждом вопросе |
| `checks/questions.json` | Только для корпусного прогона: содержит реальные цитаты, поэтому исключён по умолчанию |
| `sample_results/`, `verification/` | Образцы и отчёты; не используются для поиска |
| `__pycache__/`, `*.egg-info/`, логи | Создаются автоматически; для Git не нужны |

Если `RAG_MODEL_CACHE`, `RAG_INDEX_DIR` или `RAG_INGESTION_OUTPUT` изменены на другие
папки внутри репозитория, добавь эти пути в `.gitignore` тоже.

В готовой поставке данные остаются для удобного первого запуска. После clone из
Git эти игнорируемые файлы сами не появятся: восстанови корпоративные исходники
и запусти OCR либо перенеси готовый canonical ingestion snapshot, затем построй
индекс. Перед `tests_rag` также нужен подготовленный корпус, а перед
`checks/run_search_checks.py` — локальный `checks/questions.json` из поставки.

Не удаляй файлы из активного снимка по одному: контрольные суммы намеренно
обнаружат неполный комплект. Отсутствующие веса можно скачать заново, индекс —
перестроить из ingestion; это не означает, что их можно удалить во время работы.

## Проверка перед коммитом

```powershell
git status --short
git diff --cached --stat
```

Если эти файлы уже отслеживаются, можно убрать их только из Git index,
сохранив локально (выполняется из корня существующего репозитория):

```powershell
git rm -r --cached --ignore-unmatch .env .venv data sample_results verification checks/questions.json
```

Удаление из Git index не очищает прежнюю историю. Если секрет уже был опубликован,
его нужно заменить. Сам push в рамках подготовки этих файлов не выполнялся.
